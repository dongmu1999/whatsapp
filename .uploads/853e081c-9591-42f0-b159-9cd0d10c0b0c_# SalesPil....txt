==================================================
一、产品定位
==================================================

开发一款供外贸销售人员使用的 WhatsApp Business AI 聊天助手。

核心工作流程：

1. 用户正常使用 Windows WhatsApp Business。
2. 用户进入某个客户的聊天窗口。
3. 用户按下全局快捷键 Ctrl+Shift+A。
4. 软件识别当前 WhatsApp 窗口。
5. 软件通过 Windows UI Automation 获取可访问的聊天消息。
6. 如果 UI Automation 获取失败，使用 OCR 识别当前可见聊天区域。
7. 如果仍然失败，允许用户手动框选截图区域或粘贴聊天内容。
8. 软件整理消息上下文。
9. 调用 DeepSeek API。
10. AI 分析客户意图、采购意向、顾虑和成交机会。
11. AI 生成三条不同策略的英文回复。
12. 软件显示英文原文、中文翻译和销售策略。
13. 用户选择回复并复制。
14. 用户自己返回 WhatsApp 发送。

软件定位为销售辅助工具，不是自动回复机器人。

禁止：
- 自动发送消息。
- 自动群发。
- 自动点击 WhatsApp 发送按钮。
- 使用非官方 WhatsApp 协议。
- 破解 WhatsApp。
- 读取 WhatsApp 私有数据库。
- 绕过登录、访问控制或加密。
- 后台持续监听客户消息。

==================================================
四、WhatsApp 聊天获取模块
==================================================

这是整个软件最重要的基础模块。

默认全局快捷键：

Ctrl+Shift+A

快捷键必须可在设置中修改。

聊天获取过程：

第一步：检测当前活动窗口。

使用 Windows API 或 pywinauto 获取前台窗口信息。

判断是否为 WhatsApp Desktop / WhatsApp Business。

支持用户配置 WhatsApp Web 浏览器窗口作为可选目标。

如果不是 WhatsApp 窗口，提示用户切换到 WhatsApp。

第二步：获取聊天标题。

优先通过 UI Automation 获取：

- 当前聊天名称。
- 客户号码（如果可访问）。
- 当前窗口标题。
- 当前聊天区域。

如果无法识别客户名称，允许用户手动选择已有客户或新建客户。

第三步：获取聊天消息。

优先使用 Windows UI Automation。

获取当前聊天界面中可以合法访问的文本元素。

尽量提取：

- 消息文本。
- 消息顺序。
- 消息时间（如果可访问）。
- 消息发送方（如果可访问）。

无法确定发送方时，标记为未知，不能随意判断。

第四步：OCR 备用。

当 UI Automation 无法读取时：

- 使用 mss 截取当前聊天区域。
- 提供聊天区域框选功能。
- 使用 OCR 提取英文、中文及常见数字。
- 保留消息顺序。
- 尽可能识别消息气泡左右位置。
- 无法判断发送方时标记未知。
- 提供识别结果预览和手动编辑。

第五步：手动备用。

如果 UIA 和 OCR 均失败：

- 提供手动粘贴聊天内容。
- 允许上传聊天截图。
- 允许用户编辑识别后的文本。
- 允许用户手动标记客户消息和销售人员消息。

第六步：消息整理。

默认分析最近 20-50 条可获取消息。

允许设置分析消息数量。

要求：

- 按时间顺序排列。
- 去除重复消息。
- 保留原始英文。
- 不随意修改客户原话。
- 记录消息来源。
- 记录识别时间。
- 记录识别置信度。
- 显示是否可能存在遗漏。
- 不得将可见消息冒充完整聊天历史。

第七步：预览确认。

提交 AI 前显示获取到的聊天内容。

用户可以：
- 编辑内容。
- 删除敏感内容。
- 选择客户。
- 修改消息发送方。
- 重新获取。
- 确认并开始 AI 分析。

绝不在后台静默收集聊天内容。

五、DeepSeek AI 接口
==================================================

V1.0 默认并完整实现 DeepSeek API。

使用 OpenAI Python SDK 兼容模式。

默认配置：

API Base URL：
https://api.deepseek.com

API Key：
用户在软件设置页面填写自己的 Key。

默认模型：
deepseek-flash

高级分析模型：
deepseek-v4-pro

模型名称必须做成可配置项，并以 DeepSeek 官方当前可用模型列表为准。不要将未经验证的模型名称写死为不可修改的常量。

接口示例：

from openai import OpenAI

client = OpenAI(
    api_key=api_key,
    base_url="https://api.deepseek.com"
)

response = client.chat.completions.create(
    model=model_name,
    messages=messages,
    response_format={"type": "json_object"},
    max_tokens=4000
)

正式实现还需要：

- API Key 安全保存。
- 网络异常处理。
- 请求超时。
- API 余额不足提示。
- Key 错误提示。
- 限流处理。
- JSON 格式验证。
- 失败重试。
- Token 用量统计。
- 调用耗时统计。
- 模型名称设置。
- Base URL 设置。
- API 连接测试。

禁止将真实 API Key 写入源码、Git、日志或明文配置文件。

API Key 优先使用 Windows DPAPI 或 keyring 加密保存。

提供 DeepSeek 连接测试按钮。

七、AI 回复建议系统
==================================================

每次分析生成三种不同策略的英文回复。

A. Professional：

专业型。

特点：
- 商务化。
- 自然。
- 专业。
- 建立信任。
- 不急于成交。

B. Sales-driven：

成交推进型。

特点：
- 推动客户给出采购数量。
- 了解目标价格。
- 了解采购时间。
- 推动下一步合作。
- 适当促成订单。

C. Relationship-building：

关系维护型。

特点：
- 维护客户关系。
- 不给客户压力。
- 适合暂时观望客户。
- 为未来合作留下空间。

每条回复必须显示：

- 英文原文。
- 中文翻译。
- 回复策略。
- 适用场景。
- 复制按钮。

支持：

- 一键复制。
- 修改英文回复。
- 重新生成。
- 更正式。
- 更自然。
- 更简短。
- 更有说服力。
- 更委婉。
- 更强成交导向。

禁止 AI 擅自承诺：
- 未确认价格。
- 未确认库存。
- 未确认 MOQ。
- 未确认交货时间。
- 未确认产品认证。
- 未确认售后政策。
- 未确认付款条件。

没有知识库依据时，先建议销售人员确认，不得编造。
